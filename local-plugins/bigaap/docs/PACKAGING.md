# Packaging

```bash
node bin/bigaap.mjs package
node bin/bigaap.mjs package --write
node bin/bigaap.mjs package --verify
```

## The boundary

Two questions, and they are not the same question:

1. **What is this plugin made of?** — the files an install places, an upgrade
   replaces, a repair verifies and an uninstall may remove.
2. **What did the user make?** — analysis workspaces, briefs, corrections,
   events, outputs. None of it is ours, and none of it ships.

Everything in the packaging rules exists to keep those two sets from touching.

**A file is managed only if this build put it there.** A file you wrote is never
managed, whatever directory it is in.

## Two gates in series

A path must be **explicitly included** *and* **not explicitly excluded**.

Either gate alone fails open: an allowlist alone ships a workspace someone
created inside `src/`, and a denylist alone ships anything nobody thought to
name.

## What never ships

25 exclusion rules, each with its reason recorded next to it — a denylist whose
entries have no stated reason gets pruned by whoever next finds it inconvenient.

| Excluded | Why |
| --- | --- |
| `node_modules/` | Dependencies are installed, never vendored |
| `.bigaap-analyzer/` | A user's project configuration, including their target brief |
| `.bigaap-observability/` | Local diagnostic events |
| `.ui-analysis/`, `workspaces/` | Analysis workspaces — captures, evidence, IR |
| `.fidelity-run/` | A fidelity run, including screenshots |
| `output/`, `outputs/` | Generated project outputs |
| `feedback/`, `corrections/` | Correction history |
| `screenshots/`, `raw/` | Screenshots; raw DOM and CSS text |
| `target-brief.json` | A user's product requirements |
| `*.png`, `*.jpg`, `*.webp`, `*.gif`, `*.pdf` | Images — a screenshot could be any of these |
| `*.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx` | Credentials |
| `events*.jsonl` | Observability events |
| `Default/`, `Profile N/`, `User Data/` | Local browser profiles |
| `*.log` | Logs, which can quote anything |
| `fixtures/`, `tests/`, `tools/`, `dist/` | Test fixtures, suites, dev harnesses, build output |
| `defects/` | Defect records reference a user's captures |

**A leak here is `blocked`, not warned about.** The manifest is what an install
copies, so an excluded file reaching it is a file reaching somebody's disk:

```
package: blocked
  BLOCKED package-excluded-file-included: workspaces/a/ir.json is in the manifest
          but must never be packaged.
          This is a defect in the exclusion rules. Do not ship this manifest.
```

## The manifest

Every entry carries:

| Field | |
| --- | --- |
| `path` | Posix-style, so a manifest written on Windows reads the same on Linux |
| `type` | One of the ten file types |
| `managed` | Always `true` for a listed file; an unmanaged file found on disk is recorded `false` so the two can be told apart in one list |
| `hash` | `sha256:…` of the contents |
| `size` | Bytes |
| `version` | The plugin version that produced it |
| `upgrade` | `replace`, `preserve` or `regenerate` |
| `executable` | Whether it is an entrypoint |
| `ownership` | `bigaap-ui-forensics` |

The manifest also carries the full version set and the exclusion rules, so a
reader can check what was kept out without having the source to hand.

## Upgrade behaviour

| | |
| --- | --- |
| `replace` | Ours. Overwrite it |
| `preserve` | Placed once; it belongs to the user now. **A filled-in target brief is the case this exists for** |
| `regenerate` | Derived from source. Rebuilt rather than copied — and a hand-edited generated doc **is** reported as modified, because the edit will be lost at the next regeneration and you should hear that now |

## Verifying

```bash
node bin/bigaap.mjs package --verify
```

Re-hashes every managed file against the manifest and reports modified, missing
and unreadable files, plus any raw control bytes.
