# Commands

**Generated from `src/cli/catalog.mjs` by `node tools/generate-command-docs.mjs`.**
Do not edit this file; edit the catalog and regenerate. A test fails if the two disagree.

Every command returns the same typed result and exits on its own code.
Add `--json` to any command to emit the result contract instead of the human summary.

## Exit codes

| Code | Status | Means |
| --- | --- | --- |
| 0 | `completed` | The work was done. |
| 0 | `completed-with-warnings` | Done, with something recorded beside it. |
| 3 | `blocked` | A gate refused it. The evidence is intact and the reason is recorded. |
| 1 | `failed` | The work broke. |
| 4 | `cancelled` | Stopped deliberately. |
| 5 | `not-attempted` | There was nothing to do. |
| 6 | `requires-user-input` | Waiting on something only you can supply. |

`blocked` and `failed` are different numbers on purpose: a job that retries on `1` must not
retry a run a gate refused, because the retry is refused identically.
`requires-user-input` is its own code so a caller prompts rather than retries.

## Project

### `bigaap init`

Creates `.bigaap-analyzer/` with configuration, a target-brief template and the project directories. Launches no browser and analyses nothing. Re-running is safe: it adds what is missing and preserves what exists, and never replaces a file without --force. The target-brief template is deliberately NOT schema-valid, so a run cannot proceed on placeholder text.

| Option | Purpose |
| --- | --- |
| `--name <string>` | Project name. Defaults to the directory name. Refused rather than sanitised if unusable. |
| `--reference <url>` | The reference URL to configure. Without one the project is `incomplete` rather than ready. |
| `--stack <string>` | Target stack adapter. `next-tailwind` is the only implemented one; another name is refused, never substituted. Default `next-tailwind`. |
| `--force` | Replace existing configuration. Without it, existing files are preserved and reported as conflicts. |
| `--non-interactive` | Fail rather than prompt. Every answer must be supplied as a flag. |
| `--dir <path>` | Where to create the project. Defaults to the working directory. Parent directories are never created. |

**Outputs:** `.bigaap-analyzer/project.json`, `.bigaap-analyzer/preferences.json`, `.bigaap-analyzer/accessibility-policy.json`, `.bigaap-analyzer/fidelity-policy.json`, `.bigaap-analyzer/stack-adapter.json`, `.bigaap-analyzer/target-brief.json`, `.bigaap-analyzer/README.md`, `.bigaap-analyzer/{workspaces,history,corrections,defects,outputs}/`

**Statuses:** `completed`, `requires-user-input`, `failed`, `not-attempted`

**Failure behaviour.** An invalid project name, an unsupported stack, a missing parent directory or an unwritable path is `failed`. Existing configuration is preserved and reported as a conflict rather than overwritten.

```bash
bigaap init --reference https://example.com
bigaap init --dir ./my-project --name storefront --reference https://example.com
bigaap init --force
```

## Analysis workflows

| `--states` | Request interaction-state evidence. |

**Outputs:** `output/design-spec.md`, `output/coverage-report.md`, `output/mode-evaluation.md`, `analysis/*.json`

## Preflight

### `bigaap blockers`

Inspects inputs, evidence, configuration and artifacts and reports every blocker it can determine locally. It does NOT launch a browser to discover a blocker it can already predict — the point is to answer "why can't I get a rebuild prompt?" without spending a capture to find out.

| Option | Purpose |
| --- | --- |
| `--for <analyze\|recreate\|adapt\|extend\|improve>` | The mode to check feasibility for. Default `analyze`. |
| `--brief <path>` | Target brief to check instead of the workspace's. |
| `--viewport <number>` | Check that this viewport's evidence is present. |
| `--state <string>` | Check that this interaction state's evidence is present. |
| `--allow-capture` | Permit checks that need a browser. Off by default. |

**Modes:** `analyze`, `recreate`, `adapt`, `extend`, `improve`

**Statuses:** `completed`, `completed-with-warnings`, `not-attempted`

**Failure behaviour.** None. This command reports; it never executes the work it is reporting on.

```bash
bigaap blockers --workspace ./ws --for recreate
bigaap blockers --workspace ./ws --for adapt --json
```

## Inspection

### `bigaap telemetry`

Local observability: events written to this machine and sent nowhere. Off by default. Named `telemetry` deliberately — that is the word people search for when they want to know what a tool collects, and hiding local recording behind a friendlier name makes it harder to audit.

| Option | Purpose |
| --- | --- |
| `--redaction <high\|balanced\|minimal>` | How aggressively to redact. Default `high`: URLs hashed, no origins kept. Default `high`. |
| `--record-origins` | Record which origins were analysed. Off by default; this is a real privacy decision and belongs to you. |
| `--allow-export` | Permit diagnostic export. Separate from recording: keeping local diagnostics and sharing them are different decisions. |
| `--confirm` | Required by `clear` and `export`. |
| `--to <path>` | Where `export` writes the redacted bundle. |
| `--limit <number>` | How many events `inspect` shows. Default 20. |

**Outputs:** `.bigaap-observability/events.jsonl`, `.bigaap-observability/config.json`

**Statuses:** `completed`, `completed-with-warnings`, `blocked`, `failed`, `requires-user-input`

**Failure behaviour.** Export without permission is `blocked` (exit 3). Clearing or exporting without `--confirm` is `requires-user-input` (exit 6). A recording failure never fails the command being observed.

```bash
bigaap telemetry status
bigaap telemetry enable --redaction high
bigaap telemetry inspect --limit 50
bigaap telemetry export --to ./diagnostics.json --confirm
bigaap telemetry clear --confirm
```

### `bigaap correct`

Files a correction against a claim and shows its whole impact — the value, the status, the affected artifacts, the readiness change and the promotion position — without changing anything. Accepting is a separate, explicit step, because a proposal nobody previewed is a proposal nobody can review.

| Option | Purpose |
| --- | --- |
| `--claim <string>` | The claim id to correct, as it appears in the evidence map. |
| `--category <factual-claim\|evidence-interpretation\|source-classification\|component-identity\|selector-classification\|token-role\|region\|confidence\|reference-scoped-preference\|project-preference\|global-rule-candidate>` | What kind of judgement this is. It decides which guards apply. |
| `--value <string>` | What the claim should say. |
| `--status <string>` | The corrected evidence status. Never above what the source kind supports. |
| `--scope <reference\|workspace\|project\|preference\|global-candidate>` | How far it reaches. Default `reference`. Default `reference`. |
| `--reason <string>` | Why. A correction with no reason cannot be reviewed. |
| `--author <string>` | Who filed it. |
| `--file <path>` | A prepared correction record to file directly, bypassing the guided flow. |

**Outputs:** `feedback/corrections/<id>.<n>.proposed.json`

**Statuses:** `completed`, `blocked`, `failed`, `requires-user-input`, `not-attempted`

**Failure behaviour.** A correction that would launder evidence is `blocked` before it is recorded. Missing fields are `requires-user-input`; nothing is invented.

```bash
bigaap correct --workspace ./ws --claim layout.container.maxWidth --category factual-claim --value 1200 --reason "the capture measured a child"
```

### `bigaap correction`

The decision half of the correction workflow. `accept` re-derives the IR, re-projects every artifact, validates them as a set, and publishes only if all of it passes — otherwise nothing is written and the previous artifacts stand. History is append-only: nothing here deletes a record.

| Option | Purpose |
| --- | --- |
| `--reason <string>` | Required by `reject`. A rejection with no reason will be re-filed by the next person to notice the same thing. |
| `--explicit` | For `promote`: assert that the pattern generalises, clearing the two-witness requirement and nothing else. |
| `--allow-evidence-reduction` | For `accept`: permit a correction that makes something unmeasurable. Refused by default — a run can look better by measuring less, and that is not an improvement. |
| `--author <string>` | Who is deciding. |

**Outputs:** `feedback/corrections/<id>.<n>.<event>.json`, `analysis/ir.json`, `output/*`

**Statuses:** `completed`, `completed-with-warnings`, `blocked`, `failed`, `requires-user-input`

**Failure behaviour.** A refused promotion, a failed re-derivation and a guard refusal are all `blocked` (exit 3): each is a decision, not a crash. Nothing is published unless every regenerated artifact validates.

```bash
bigaap correction show corr_0001 --workspace ./ws
bigaap correction accept corr_0001 --workspace ./ws
bigaap correction reject corr_0001 --reason "measured again; the original was right"
bigaap correction promote corr_0001 --explicit
bigaap correction history --workspace ./ws
```

## Installation

### `bigaap version`

The tool version, the plugin manifest version, eight schema versions, and the extractor, driver, tolerance and policy versions — plus the running Node and whether it satisfies the requirement. Launches nothing and reads no project. When package.json and .claude-plugin/plugin.json disagree it reports both rather than choosing: preferring one silently would make the other permanently wrong.

| Option | Purpose |
| --- | --- |
| `--check <string>` | Check one artifact kind's version for readability, e.g. --check correction-record --version 0. |
| `--version <string>` | The version to check, with --check. |

**Statuses:** `completed`, `blocked`, `failed`

**Failure behaviour.** `failed` only when this build cannot read its own version — a damaged installation. `blocked` when --check names a version this build cannot read.

```bash
bigaap version
bigaap version --json
bigaap version --check observability-event --version 0
```

### `bigaap doctor`

Nine checks: runtime, this build's own version, the managed directory layout, plugin metadata, the entrypoint, the Playwright package, a browser binary, documentation and writability. **No browser is launched.** Browser presence is a filesystem question, and it has three answers — yes, no, and could-not-determine — because reporting the third as `no` sends people to reinstall a browser they already have.

| Option | Purpose |
| --- | --- |
| `--allow-browser-launch` | Permit a launch-based check. This build implements none, and says so rather than silently doing nothing. |
| `--root <path>` | The installation to check. Defaults to this one. |

**Statuses:** `completed`, `completed-with-warnings`, `blocked`

**Failure behaviour.** `blocked` when something is missing that the tool cannot work without. A missing browser is a warning, not a blocker — analysis from existing captures, validation, prompts, corrections and readiness all work without one.

```bash
bigaap doctor
bigaap doctor --json
```

### `bigaap install`

Three modes: `repository` (a checkout IS the installation — nothing is copied), `global` (~/.claude/plugins) and `project` (./.claude/plugins). Idempotent: a file already identical is skipped, so a second run reports everything current rather than rewriting identical bytes. **Never overwrites a file it did not write.** A destination file whose hash differs from the manifest is a conflict: it is named, preserved, and the run is `blocked` until you decide. Requires no Docker.

| Option | Purpose |
| --- | --- |
| `--mode <repository\|global\|project>` | Where to install. Default `repository`. |
| `--apply` | Perform it. Without this the command is a dry run and writes nothing. |
| `--force` | Replace conflicting files. Each is backed up first. |
| `--backup <path>` | Where to put backups of replaced files. |
| `--project <path>` | Project root, for --mode project. |

**Outputs:** `package-manifest.json`

**Statuses:** `completed`, `blocked`, `failed`, `not-attempted`

**Failure behaviour.** `blocked` on a conflict — the files are intact and re-running unchanged refuses identically. `failed` on a permission error, and then NO manifest is written, so the installation is marked incomplete rather than looking finished.

```bash
bigaap install
bigaap install --mode global
bigaap install --mode global --apply
```

### `bigaap upgrade`

Replaces managed files, preserves everything placed once, and runs configuration migrations. A target brief you filled in is never replaced. Refuses to install older code over a newer installation unless forced, because that leaves files the older build cannot read. Refuses to adopt files it has no record of installing.

| Option | Purpose |
| --- | --- |
| `--mode <repository\|global\|project>` | Which installation to upgrade. Default `global`. |
| `--apply` | Perform it. |
| `--force` | Replace conflicting files, and permit a downgrade. Each replaced file is backed up. |
| `--backup <path>` | Where to put backups. |
| `--no-migrate` | Skip configuration migrations. |

**Outputs:** `package-manifest.json`

**Statuses:** `completed`, `blocked`, `failed`, `requires-user-input`, `not-attempted`

**Failure behaviour.** `requires-user-input` when there is nothing installed to upgrade. `blocked` on a conflict or an attempted downgrade.

```bash
bigaap upgrade --mode global
bigaap upgrade --mode global --apply --backup ./backup
```

### `bigaap uninstall`

Six separately-selectable categories: plugin code, project configuration, generated outputs, analysis evidence, correction history and observability events. **Only plugin code is removed by default.** Every irreversible category must be confirmed by name — a blanket --confirm is refused, because saying yes to removing code is not consent to losing a correction history. The dry run reports what would go, what would stay, what is unmanaged, the size of each, and which operations cannot be undone.

| Option | Purpose |
| --- | --- |
| `--remove <list>` | Categories to remove, comma-separated. Default `plugin-code`. |
| `--confirm <list>` | Irreversible categories you are confirming, by name. |
| `--apply` | Perform it. |
| `--project <path>` | Project root holding the data categories. |

**Statuses:** `completed`, `completed-with-warnings`, `requires-user-input`, `failed`

**Failure behaviour.** `requires-user-input` when an irreversible category was selected but not confirmed by name. Unmanaged files are always left in place and reported.

```bash
bigaap uninstall
bigaap uninstall --apply
bigaap uninstall --remove plugin-code,observability-events --apply --confirm observability-events
```

### `bigaap repair`

Hashes every managed file against the manifest and reports four states: ok, modified, missing and unreadable. Restores missing files. **Never overwrites a modified file without --force**, because this build cannot tell a deliberate edit from a corruption. Also reports raw control bytes in managed sources — inside a regex literal one silently changes what the pattern matches, which is how a test assertion here became unable to fail (def_0038).

| Option | Purpose |
| --- | --- |
| `--apply` | Restore missing files. |
| `--force` | Also restore modified files. Each is backed up first. |
| `--backup <path>` | Where to put backups. |
| `--root <path>` | The installation to repair. Defaults to this one. |

**Statuses:** `completed`, `completed-with-warnings`, `requires-user-input`

**Failure behaviour.** `requires-user-input` when managed files were modified — nothing refused them on the evidence; the tool is waiting for a person to say whether their edit should survive.

```bash
bigaap repair
bigaap repair --apply
bigaap repair --apply --force --backup ./backup
```

### `bigaap migrations`

Migrations may add a field or rename one. They never reinterpret a value. Evidence and correction-record content are never rewritten — a correction says what someone believed on a date, and that does not become false when the tool changes. An ambiguous legacy status is refused by name rather than guessed: `error` meant both `failed` and `blocked` depending on the caller, and choosing one would fabricate a distinction nobody recorded.

| Option | Purpose |
| --- | --- |
| `--list` | List every migration, including the ones that deliberately do not exist and why. |
| `--apply` | Perform them. |
| `--backup <path>` | Back up each file before migrating it. |
| `--root <path>` | Project root to migrate. Defaults to the working directory. |

**Statuses:** `completed`, `completed-with-warnings`, `not-attempted`

**Failure behaviour.** None. A migration that cannot be made without guessing is refused and reported as a warning; the file is left exactly as it is.

```bash
bigaap migrations
bigaap migrations --list
bigaap migrations --apply --backup ./backup
```

### `bigaap package`

Enumerates every managed file with its path, type, managed status, hash, version, upgrade behaviour and ownership. The exclusion rules travel with the manifest so a reader can see what was kept out. A workspace, screenshot, target brief, correction record, observability event or credential file reaching the manifest is `blocked`, not warned about: the manifest is what an install copies, so a leak here is a leak onto somebody's disk.

| Option | Purpose |
| --- | --- |
| `--write` | Write package-manifest.json. |
| `--out <path>` | Write it somewhere else. |
| `--verify` | Check the files on disk against an existing manifest. |
| `--root <path>` | The installation to describe. Defaults to this one. |

**Outputs:** `package-manifest.json`

**Statuses:** `completed`, `completed-with-warnings`, `blocked`, `failed`, `not-attempted`

**Failure behaviour.** `blocked` when an excluded file reached the manifest — that is a defect in the exclusion rules and the manifest must not ship.

```bash
bigaap package
bigaap package --write
bigaap package --verify
```

## Not available

These are absent from the surface because they do not exist, not because they were
forgotten. A command name is read as a statement of capability.

- **Authenticated capture.** No command accepts credentials, and none bypasses a consent
  gate, a CAPTCHA or a bot check. This is a scope decision and will not change.
- **Automatic component-level correction.** A permanent limitation (`def_0030`).
  Category-level comparison is the ceiling.
- **Unattended execution.** The CLI is built for an operator reading results, and the run
  directory is not concurrency-safe.
